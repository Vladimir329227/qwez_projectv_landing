# 🔒 Улучшения безопасности XSS защита

## Обзор изменений

В проекте были внесены изменения для защиты от XSS (Cross-Site Scripting) атак.

---

## ✅ Что было исправлено

### 1. **NameForm.tsx** - Защита имени пользователя

**До:**
- Минимальная валидация (только длина)
- Нет санитизации входных данных
- Возможность ввода HTML тегов, скриптов и других опасных символов

**После:**
- ✅ Добавлена функция `sanitizeName()` для удаления опасных символов
- ✅ Добавлена функция `validateName()` с комплексной проверкой:
  - Минимум 2, максимум 50 символов
  - Только буквы, пробелы, дефисы и апострофы
  - Удаление HTML тегов, JavaScript кода, event handlers
- ✅ Автоматическая санитизация при отправке формы

**Примеры блокируемых атак:**
```javascript
// Эти примеры теперь безопасно фильтруются:
"<script>alert('XSS')</script>"
"John<img src=x onerror=alert(1)>"
"Jane' onclick='alert(1)'"
```

---

### 2. **telegramSender.ts** - Экранирование HTML в Telegram сообщениях

**До:**
- Пользовательский ввод (имя, email, пол) напрямую вставлялся в HTML сообщение
- Потенциальная XSS атака при отображении в Telegram

**После:**
- ✅ Добавлена функция `escapeHtml()` для экранирования HTML символов:
  - `&` → `&amp;`
  - `<` → `&lt;`
  - `>` → `&gt;`
  - `"` → `&quot;`
  - `'` → `&#x27;`
- ✅ Все пользовательские данные экранируются перед отправкой в Telegram

---

### 3. **EmailForm.tsx** - Защита email адресов

**До:**
- Email передавался без санитизации

**После:**
- ✅ Добавлена функция `sanitizeEmail()`:
  - Удаление HTML тегов
  - Блокировка javascript: протокола
  - Ограничение длины до 254 символов
  - Автоматическая санитизация при отправке

## 🛡️ Как это работает

### NameForm - Процесс валидации

```typescript
// 1. Пользователь вводит имя
setName("<script>alert('XSS')</script>")

// 2. Функция sanitizeName() удаляет опасные символы
sanitizeName("<script>alert('XSS')</script>") 
// → "" (пустая строка после удаления тегов)

// 3. Функция validateName() проверяет:
// - Длина < 2 → "Please enter at least 2 characters"
// - Длина > 50 → "Name cannot exceed 50 characters"  
// - Несоответствие regex → "Name can only contain letters..."

// 4. При отправке - автоматическая санитизация
onNext(sanitizeName(name))
```

### TelegramSender - Экранирование HTML

```typescript
// Входные данные
userInfo.name = "John <script>alert(1)</script>"

// После escapeHtml()
escapeHtml("John <script>alert(1)</script>")
// → "John &lt;script&gt;alert(1)&lt;/script&gt;"

// Безопасно вставляется в HTML:
`<b>Пользователь:</b> John &lt;script&gt;alert(1)&lt;/script&gt;`
```

## 📋 Рекомендации для дальнейшего развития

### 1. Добавить CSP Headers
Рекомендуется добавить Content Security Policy headers:

```html
<meta http-equiv="Content-Security-Policy" 
      content="①script-src 'self'; 
               object-src 'none'; 
               base-uri 'self';">
```

### 2. Проверить QuizResult компоненты
В компонентах `QuizResultMobile`, `QuizResultTablet`, `QuizResultDesktop` имя пользователя вставляется так:
```tsx
{`Hey ${answers.name || 'there'}, here is your wellness profile revealed:`}
```

**Статус**: ✅ Безопасно. React автоматически экранирует содержимое JSX выражений.

### 3. Рассмотреть библиотеки
Для более сложных сценариев можно использовать:
- `DOMPurify` - для санитизации HTML
- `validator.js` - для валидации входных данных
- `xss` - для защиты от XSS атак

### 4. Backend валидация
⚠️ **ВАЖНО**: Санитизация на фронтенде не заменяет валидацию на бэкенде!
Обязательно добавьте проверку пользовательских данных на сервере.
